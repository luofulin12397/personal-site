# 全站版式与首页重排

首页是在只有一个项目拆解时搭出来的，之后分区从两个长到三个、拆解从 1 篇长到 3 篇、文章栏目上线，首页只是不断往上加区块。结果是：同一件事有三个入口、首页数字讲的是 RAG 而不是这个人、各页区块骨架各不相同。我们决定把全站收拢到 `DESIGN.md` Layout 里的一套外框、三种区块骨架、四档断点，并按下面的顺序重排首页。

## 盘点到的问题（2026-11-28，对照 `8c803de` 线上版）

**首页**
1. **项目拆解入口重复三次**：首屏 CTA「看 RAG 项目拆解」、项目条目里的 `BRANCH 02` 整行、独立的 `#branch` 整块。整块入口的说明只列出 RAG 与医疗风控，漏了 WrenAI。
2. **首屏事实条是 RAG 的内部指标**（独立服务进程 02 / 文档导入节点 07 …），违反「分区各答各的问题」；读者在首页看不懂这些数字指什么。
3. **首屏 CTA 指向单个项目**，但按钮文案、`BRANCH.cta`、DESIGN 里「CTA 进入 02 项目拆解」三处说法不一致。
4. **终端旁说明写着「右边这个终端」**，而终端在左栏。
5. **WrenAI 混在「我做的项目」第一位**，而它是上游项目的源码学习；导语又说「分布在四个仓库里」，数字对不上。
6. **03 文章在首页只占一个列表区块**，与升格为一级分区的地位不符；文章与学习资源没有被看见。
7. 首屏在 1440px 下：左上命题 + 右上导语之后，终端区又是一组双栏，**两组双栏比例不同**（1.15:0.85 与 1.25:0.75），左边界不齐。

**全站**
8. 断点散落为 1100 / 1080 / 1000 / 980 / 900 / 860 / 760 / 620 / 480 九档。
9. 三篇拆解页头与区块结构不一致：RAG 与 WrenAI 有 `01–06` 编号，医疗风控的区块没有 `kicker` 编号。
10. 共识文档前半截描述已废弃的 v2 视觉，现行规则藏在末尾补丁里（本次已重写，历史移到 `docs/history.md`）。

## 决定：首页区块顺序

| # | 区块 | 骨架 | 内容 |
|---|---|---|---|
| 0 | **首屏** | B | 左：eyebrow + 命题大标题 + 一句话定位（名字、方向）。右：导语 + **唯一主 CTA「进入 02 项目拆解」**（指向目录，不指向单个项目）。下方一行「三个分区」索引：`01 这里讲人和项目 / 02 三篇项目拆解 / 03 文章与学习资源`，每项一句话 + 文字链接。 |
| 1 | **01 关于我** | B | 左三段第一人称介绍；右「在做 / 在写 / 在意」三行。 |
| 2 | **02 项目** | A | 两组：**有拆解的**（RAG 知识库、AI_RISK_HEALTH、WrenAI·源码学习）在前，每条带整行拆解入口；**其余仓库**（smart-bi、log-patrol、ai-learning-site、personal-site）在后，紧凑横行，只有名字、语言、一句话、事实行。WrenAI 标「上游源码学习」，不计入仓库数。 |
| 3 | **03 在写与分享** | A | 已成篇文章（标题 + 一句判断 + 字数/读时）→ 学习资源一行 → 排队题目各一句进度；末尾文字链接进 `03 文章`。 |
| 4 | **真终端** | B | 左终端、右说明（文字方位写对）。事实条改成本站数字：`3` 篇项目拆解 / `1` 篇长文 / `6` 个仓库 / `13` 个可点节点（WrenAI）——或删掉事实条，二选一，实施时看截图定。 |
| 5 | **04 取舍** | A | 四条不变。 |
| 6 | **05 这一页本身** | A | 内容更新为三分区现状。 |

**删除**：独立的 `#branch` 整块区块（它的作用由首屏 CTA + 三分区索引 + 项目条目入口 + 顶栏常驻切换器承担）。

**为什么终端从首屏挪到第 4 位**：首屏要先回答「是谁、三个分区是什么」；终端是「这个人怎么做东西」的证据，属于后半段。代价是首屏少了唯一可交互的东西——如果实施后首屏显得太空，备选是把终端保留在首屏右栏、把导语移到命题下方，由截图决定，不再改文档。

## 决定：全站统一

- 所有页面区块只用 `DESIGN.md` 的 A / B / C 三种骨架；B 骨架比例在同一页内必须一致。
- 断点收拢为 1100 / 980 / 760 / 480 四档。
- 医疗风控页补齐 `01 / …` 编号与 ADR 0001 的章节语法。

## 迁移（实施顺序）

1. 首页按上表重排（`src/pages/Home.tsx`、`src/data/home.ts`、`src/styles/home.css`），修正 1–7。
2. 断点收拢（逐个样式文件，改完对 1440 / 1100 / 980 / 760 / 390 截图）。
3. 医疗风控章节编号。
4. `scripts/shoot.cjs` 增加下面的版式检查。

## 验收

在 `scripts/shoot.cjs` 现有门槛（无横向溢出、无 < 12px 文字、对比度、断链、控制台零报错、两套 base）之外，增加：

- **首屏**（1440×900）：可见名字、主 CTA、三个分区入口；同屏信号色实心块 ≤ 2。
- **入口唯一**：首页指向 `/projects/` 目录的主按钮只有 1 个；每篇拆解在首页至多出现 1 个入口。
- **行宽**：01 / 02 页面中，任何 `p` 的渲染宽度 ≤ 68ch（约 1020px @15px）；任何 `.section` 的宽度等于 `.wrap` 内容宽度。
- **左边界**：同页所有区块标题的 `left` 相同（误差 ≤ 1px）。
- **数字归属**：首页 `.facts` 中不出现单个项目的内部指标。

## 被否决的方案

- **首页只留自我介绍，项目全挪到 02**：同行从 profile 点进来，首页看不到做过什么就会关掉。
- **保留 `#branch` 整块、删掉项目条目里的入口**：读者在项目条目处最想点进去，入口应该在那里。
- **按项目做首页卡片网格**：条目等价、信息量不同，卡片会把短的撑空、长的截断；继续用横行。
