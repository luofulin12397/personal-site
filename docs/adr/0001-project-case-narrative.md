# 项目拆解统一叙事合同

三个项目拆解页已经各自长成不同的阅读结构：RAG 是编号章节，医疗风控是工作台加取舍，Wren 是三视图切换。读者无法把同一套阅读预期带到下一篇。我们决定以 RAG 为叙事参照，但不复制它的页面形状：所有项目拆解共用一条七拍主线、一套章节语法和第一人称叙述；复杂案例的多条真实路径改为同页连续章节，不再藏在切换器后面。

## 七拍主线

1. **具体问题**：用一笔请求或一次任务提出工程问题，并在首屏给出结论的方向。
2. **系统剖面**：先让读者看见结构，再进入细节。复杂案例可以包含多条视图，但每条视图必须是连续章节。
3. **边界**：说明系统负责什么、不负责什么，哪些是外部依赖、复用模块或配置。
4. **路径**：追一条真实链路，保留会改变结果的条件分支、短路、兜底或人工接手点。
5. **代码与取舍**：用最小源码片段解释一个决定：选了什么、为什么不选另一种、代价是什么、何时失效。
6. **证据**：让结论能回到固定提交里的函数或行段；区分当前实现、设计意图和文档差异。
7. **未验证与局限**：明确哪些没有测、哪些只覆盖特定入口；不要用演示结果暗示生产结论。

简单案例可以合并相邻两拍，例如把“路径”和“证据”放在同一节；顺序不能重排。

## 章节语法与声音

- 每个案例从 `01` 开始编号；章节标题使用 `编号 / 英文标签`、中文标题和一致的短导语。
- 正文统一第一人称，用“我 / 这一页”；不使用“作者认为”这类第三人称转述。
- 工作台、代码块、证据列表沿用 `tokens.css`、`case.css` 与现有组件语法，不另起一套视觉系统。
- 多视图案例的视图名称是章节坐标，不是独立产品；切换视图不能成为阅读前提。

## 版面与空间合同（与 03 文章区分）

- **容器对齐 `.wrap`，只收窄段落行宽**：`02 项目拆解` 的 `.case-head` 与所有 `.section` 统一占满 `.wrap` 网格，禁止把整节容器缩成 `03 文章` 式的单列窄栏（如 `max-width: 76ch` 居中孤岛），避免两侧大面积留空或同页多种版心跳变；仅导语与说明段落限制在 `60–68ch`。
- **首屏固定分支徽标与实例对照**：页头顶部统一渲染 `.branch-badge`（`02 · 项目拆解 / PROJECT BREAKDOWN`）；复杂案例首屏可左列放命题与入口、右列放最小输入输出样本。
- **系统剖面紧随首屏且桌面双栏并置**：第二拍 `.workbench`（`2px` 信号色顶线）紧接首屏之后，桌面端保持「左 System Map + 右 Evidence Inspector（含底部源码证据条）」双栏对照，窄屏就地展开详情；多条真实路径在同一剖面内分泳道同时呈现。高纵横比外部导出位图不缩小硬塞进窄栏以免图内字号跌破 `12px`，改为原尺寸外链。
- **代码、对照与取舍横向展开**：代码摘录配判断说明、单变量失败对照配原始输出、设计取舍用 `.rows` 横行、源码索引用 `.evidence` 列表，减少单列纵向堆叠。

## 影响

- WrenAI 按本合同对齐 `.wrap` 全宽网格：首屏补齐 `.branch-badge` 与三笔订单样本卡，紧接双栏三泳道工作台（构建 / 查询 / 运行边界同图可见、共用右侧 Inspector），后续依次展开边界、查询链路、失败对照、关键取舍、命令实测与局限。
- 医疗风控与 RAG 的章节迁移仍未完成；后续按同一合同补齐编号、路径和证据位置。

## 被否决的方案

- **完全复制 RAG 的页面形状**：RAG 的 12 节点图不适用于所有项目，复制会把内容挤进同一个模板。
- **只统一页头和色板**：这会保留“页头像兄弟、正文像不同作者”的问题，已经被实践否定。
- **把 Wren 三视图拆成三个独立页面**：读者失去横向对照，节点证据也会被切碎。
- **继续用 tab 隐藏视图**：它让同一案例的两条路径不可同时扫读，也不符合其他案例的连续阅读方式。
- **把项目拆解排成单列窄栏教程**：整节锁进 `76ch` 会让桌面视口损失逾半宽度、分隔线断裂，并迫使工作台退居页尾附录。
